1. The Role of the Operating System:
In this mini-project, our Python script simulated the major responsibilities of an Operating System. 
Match the specific code behavior in `ultimate_cluster_os.py` to the corresponding OS concept you learned throughout the semester:

- File System & Permissions (Lab 9): 
  [Explain which line of code simulated this and why Workload D failed]
  Answer: จำลองด้วยคำสั่ง `if not os.path.exists(dataset_path):` ในฟังก์ชัน `_execute_job` 
  สาเหตุที่ Workload D ล้มเหลว: จากผลการรันจริง พอ Workload D ร้องขอไฟล์ชื่อ `secret_keys.txt` ซึ่งไม่มีอยู่จริงในระบบ ตัว OS 
  จะตรวจสอบเส้นทางไฟล์และบล็อกทิ้งทันที โดยขึ้นข้อความแจ้งว่า FAILED ตั้งแต่หน้าด่าน ทำให้โปรเซสถูกดีดออกจากระบบทันทีโดยไม่หลุดเข้าไปจอง RAM หรือ GPU 
  ช่วยป้องกันไม่ให้โปรเซสที่ผิดพลาดหรือไฟล์อันตรายเข้ามาเปลืองทรัพยากรส่วนกลาง

- Memory Management (Labs 5/6):
  [Explain how the OS prevented Thrashing by using the `while` loop for RAM allocation]
  Answer: จำลองด้วยลูป `while True:` ที่คอยตรวจสอบว่า `if self.available_ram_gb >= req_ram:` ร่วมกับการใช้ `ram_lock` 
  วิธีป้องกัน Thrashing: OS จะไม่อนุญาตให้โปรเซสเริ่มทำงานจนกว่าจะมี Physical RAM ที่ว่างอยู่จริงเพียงพอกับที่งานนั้นขอ ถ้า RAM ยังไม่พอ 
  ตัวโปรเซสจะต้องติดอยู่ในลูปและหลับรอ (Sleep/Wait) ไปก่อน การทำแบบนี้ช่วยป้องกันไม่ให้ระบบแจกจ่าย RAM เกินความจุจริง (Overcommit) 
   Thrashing และต้องคอยสลับข้อมูลลง Swap บนดิสก์จนเครื่องค้าง

- Concurrency & Deadlocks (Labs 3/4):
  [Explain how the OS sorted the requested GPUs to avoid Circular Wait deadlocks]
  Answer: จำลองด้วยคำสั่ง `sorted_gpus = sorted(req_gpus)` แล้วค่อยสั่งล็อกทีละตัวตามลำดับ `for gpu in sorted_gpus: self.gpu_locks[gpu].acquire()` 
  การแก้ปัญหา Deadlock: เป็นการนำกฎ Resource Hierarchy มาใช้ทำลายเงื่อนไขการรอคอยเป็นวงกลม (Circular Wait) เช่น ตอนส่งงาน Workload A เข้ามา 
  มันขอการ์ดจอเป็น [2, 1, 0] แต่โค้ดจะจับเรียงลำดับใหม่ให้จอง GPU 0 ก่อน ตามด้วย 1 และ 2 เสมอ ทำให้ทุกโปรเซสต้องต่อคิวจองทรัพยากรไปในทิศทางเดียวกัน 
  จึงไม่มีโอกาสที่โปรเซสสองตัวจะถือการ์ดจอสลับกันแล้วนั่งรอค้างกันเองแบบ Deadlock

 and Workload C (Inference) AT THE SAME TIME without crashing. Why didn't they block each other?

จากที่สังเกตบน Live Dashboard ทั้ง 3 งานสามารถรันไปพร้อมกันได้โดยไม่ชนกันและไม่ค้างเลย เพราะ OS จัดสรรทรัพยากรตามที่แต่ละงานต้องการได้อย่างพอดี:

 ซึ่งไม่เกินขนาดจริงของเครื่อง ทำให้ทุกงานได้ RAM ครบและเริ่มงานได้พร้อมกันทันที
2. ด้าน GPU:

ทำให้ฮาร์ดแวร์ทั้ง RAM, CPU และ GPU ทั้ง 4 ใบ ถูกดึงมาทำงานเต็มประสิทธิภาพพร้อมกัน 100% โดยไม่มีงานไหนต้องนั่งรอใคร
